# Project Setup — 2026-10-21

## What was done
- Cloned repo `Project-Submission-Manager` from GitHub, no commits made yet
- Scaffolded `client/` with Next.js (TypeScript, TailwindCSS, App Router, src dir)
- Scaffolded `server/` with Express + TypeScript, pinned `prisma`/`@prisma/client` to `6.19.3` (avoided the newer 7.x/8.x RC lines for stability)
- Added `docker-compose.yml` running Postgres 16 (alpine) locally
- Defined Prisma schema: `User` (role: STUDENT/ADMIN) and `Submission` (status: PENDING/APPROVED/REJECTED), one-to-one relation between them to enforce one submission per student
- Ran initial migration (`init`) successfully against the local Postgres container

## Decisions made
- Monorepo layout: `client/` + `server/` in a single repo
- Duplicate-submission rule: one submission per student total (enforced via unique `studentId` on `Submission`)
- Local Postgres via Docker Compose (not a cloud DB) for development

## Issues encountered
- Docker container port 5432 conflicted with an existing native Windows PostgreSQL service
- Port 5433 also conflicted with a second native Postgres service bound there, causing silent auth failures (connections were routed inconsistently between the native service and the container by Windows)
- Resolved by mapping the container to host port `5434`, confirmed free via `netstat`, updated `DATABASE_URL` in `server/.env` accordingly
